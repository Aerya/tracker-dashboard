Moteur navigateur

Par défaut, les lectures en mode navigateur utilisent Chromium (Playwright). CloakBrowser est un Chromium modifié au niveau source pour ressembler à un vrai navigateur côté empreinte (TLS, fingerprint), ce qui lui permet de franchir davantage de protections anti-bot — notamment certains challenges Cloudflare Turnstile qui se valident automatiquement — donc moins de sites nécessitant un cookie collé à la main. Mêmes performances qu'un Chromium classique (c'est un navigateur complet). Si le moteur est indisponible, l'app repart automatiquement sur Chromium.

Runtime navigateur …
Repli Cloudflare (FlareSolverr) …

Dernier recours automatique pour les challenges Cloudflare/anti-bot explicites. CloakBrowser reste le moteur normal ; les erreurs de credentials ou de regex ne déclenchent pas FlareSolverr.

Utilise curl-impersonate (empreinte TLS de vrai navigateur) pour franchir le filtrage anti-bot passif sans lancer Chromium : le login HTTP complet pour les trackers en mode HTTP, et une requête directe pour les trackers navigateur disposant d'un cookie. En cas d'échec (page JS, session expirée, binaire absent), l'app retombe automatiquement sur la voie normale — aucune lecture cassée.

Proxys spécifiques par tracker

Surcharge le proxy global pour les trackers cochés. Choisir Direct sans proxy permet à un tracker de sortir hors proxy global. Un tracker ne peut être couvert que par un seul override actif à la fois.

Besoin d'un proxy rotatif auto-hébergé pour les sites qui bannissent une IP fixe ? Regardez par exemples du côté de Magpie, ProxySpin ou encore Rota.

Clients BitTorrent

Le champ « Auto (min) » de chaque client définit son rafraîchissement automatique en arrière-plan (0 = désactivé). Le bouton ci-dessous force une synchronisation immédiate de tous les clients.

Instances cross-seed

Reliez chaque instance cross-seed à tous les clients BitTorrent qu'elle alimente. Les marqueurs correspondent au linkCategory, à une catégorie se terminant par .cross-seed, ou à un tag appliqué aux torrents injectés.

Associations BitTorrent

Associer les torrents détectés dans les clients BitTorrent aux trackers actifs quand ils ne sont pas reconnus automatiquement.

Affichage

Active ou masque les fonctions graphiques de l'interface. Les données restent conservées.

Planification des logins (AutoVisit)

Planification du scraping des trackers, inspirée d'Autovisit : une planification globale et, plus bas, une fréquence individuelle par tracker. Chaque cycle visite tous les trackers actifs disposant de credentials.

Canaux de notification

Chaque canal est une destination indépendante. Les notifications sont envoyées sur tous les canaux actifs.

Discord — coller l'URL du webhook (Paramètres salon → Intégrations → Webhooks).
Apprise — URL de votre serveur Apprise + une ou plusieurs URLs de service (Pushover, Telegram…).
Mail — envoi via votre serveur Apprise. Nécessite un canal Apprise actif.

Notifications globales

S'appliquent à tous les trackers. Le bouton choisit le mode édité. Les seuils ratio / buffer / session sont communs aux deux modes.

Notifications par tracker

Notifications spécifiques à un tracker, envoyées dans une notification distincte de la globale. Sélectionnez un tracker, puis activez les options voulues (mêmes options que les notifications globales).
